VaporPkg

AI assistants sometimes recommend packages that do not exist, and attackers register those names with malware. VaporPkg checks every package an AI tells you to install against PyPI and npm before you run the install.

How it works

  1. Find the package names.

    Install commands (pip, uv, poetry, npm, pnpm, yarn, npx, uvx and more), import statements, code blocks, requirements.txt, package.json and pyproject.toml. Local paths, URLs and Git references are skipped.

  2. Ask the registry.

    Does the name exist on PyPI or npm? When was it first published, how many releases, is a source repository linked, does it run install scripts, is it on the OpenSSF malicious-packages list?

  3. Compare with popular names.

    A name a typo or a suffix away from one of the 5,000 most-downloaded packages (reqeusts, py-numpy) is a classic trap.

  4. Score and decide.

    Each warning sign adds points. 70 or more blocks the install, 30–69 warns. A name that does not exist, or is known malware, is always blocked.

  5. Guard the install.

    The command-line tool wraps pip install and npm install and only runs them when nothing is blocked. It also ships as a pre-commit hook and a GitHub Action with SARIF output for code scanning.

Limits

  • A package that exists and looks established can still be malicious; VaporPkg catches made-up names and risky signs, not every attack.
  • Registry facts change. A made-up name can be registered by anyone tomorrow, which is why the tool re-checks missing names every hour.
  • Download counts (pypistats.org, api.npmjs.org) and the OSV malware check are used when the browser can reach them; when it cannot, those signals are skipped, exactly as the command-line tool does after a network error.
  • This page is a JavaScript port of the Python tool. On every example here it produced the same verdicts, scores and SARIF as the Python code, including its parsing of 20 tricky AI answers and 412 typo cases.
